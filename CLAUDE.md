# Атлас — личный ассистент

Личный ИИ-ассистент одного человека (владелец) плюс доступ только к контент-плану для его девушки. Работает на своём VPS, общается через веб-интерфейс, Telegram Mini App и два Telegram-бота. Мозг — Claude API.

## Правила работы (важно)

- **Общение по-русски.** Объясняй подробно и пошагово прямо в чате, с готовыми командами. Не отправляй «прочитать DEPLOY.md» — пересказывай нужные шаги сам.
- **Не пиши код без явного «делай».** На вопрос сначала отвечай и предлагай варианты.
- **Перед пушем на GitHub опиши, что сделал, и жди «добро»/«пушь».** Коммитить локально можно, пушить без согласия нельзя.
- **Ветка:** работа идёт прямо в `main`, сервер обновляется из `main`. Старая ветка `claude/blissful-dijkstra-h1poer` больше не используется.
- **Секреты только в `.env` на сервере.** Никогда не проси прислать в чат токены ботов, ключи API, пароли, хеши паролей. Чтобы сравнить ключи, используй `sha256sum`, а не вывод значения.
- **Не ломать SSH-доступ владельца к серверу сайта Forbsa.** У Атласа нет и не должно быть доступа к серверу сайта: только чтение двух адресов по ключу (лента заявок и статус).
- **Персональные данные клиентов сайта** (имя, телефон, почта, текст обращения) не уходят ни в Telegram, ни в модель.
- **Девушка видит только контент-план** и получает только его уведомления. Больше ничего.
- **Личная часть Атласа закрыта**, доступ к ней только через Tailscale.
- **Тексты пользователю пишутся простым текстом,** без Markdown-звёздочек (Telegram их не рендерит).

## Сервер

- VPS SmartApe (Чехия), Ubuntu 26.04, пользователь `atlas`, вход только по SSH-ключу. На Mac есть алиас: `ssh atlas`.
- Атлас лежит в `~/atlas`, запускается через Docker Compose: сервис `atlas`, том `atlas-data` → `/data`.
- Личный доступ к Атласу через Tailscale (`https://<имя>.ts.net`, `tailscale serve` на :443). Сервер настроен как Tailscale exit node.
- Публичный адрес только для контент-плана: `https://contentplanpoliinag.dpdns.org` (Caddy, `default_bind` на публичный IP, наружу пускаются только `/api/content*` и вход).
- Cockpit доступен через Tailscale.
- Сайт Forbsa (forbsa.ru) работает на отдельном сервере в России. Атлас каждую минуту проверяет `/api/health` и ленту заявок (ключ `SITE_FEED_KEY`), раз в 5 минут читает status.json. Дополнительно сайт мониторит Better Stack, без Telegram: уведомления там платные.
- Если сервер ещё смотрит на старую ветку, переключение на `main`: `git fetch origin && git checkout main && git pull`.

**Обновление на сервере:**
```bash
ssh atlas
cd ~/atlas && git pull && docker compose up -d --build
docker compose logs --tail 20 atlas      # ждём строку "Atlas started"
```
После правки `.env`: `docker compose up -d --force-recreate`.

**Подводные камни:**
- При самом первом успешном опросе ленты Атлас запоминает последний номер заявки и присылает только новые. Поэтому `/leads` пуст, пока не пришла новая заявка. Это нормально.
- 401 в «Ошибка опроса заявок» — не совпадает `SITE_FEED_KEY` у Атласа и ключ ленты в `.env` сайта.
- Контейнер работает с файловой системой только для чтения и под uid 10001. `.env` монтируется внутрь, поэтому права должны быть `644` (с `600` Атлас не стартует: Permission denied). Писать можно только в `/data` и `/tmp`.
- `git pull` не трогает `.env`. Новые переменные есть в `.env.example`, почти у всех есть значения по умолчанию в `app/config.py`.

## Стек и структура

- Бэкенд: Python 3.12, FastAPI, SQLAlchemy async + SQLite, Alembic (миграции `alembic/versions/0001…`), APScheduler, pydantic-settings.
- Фронтенд: React + Vite + TypeScript в `frontend/`, сборка кладётся в `app/web` (в git не хранится).
- `app/main.py` — сборка приложения: роутеры, фоновые задачи, оба бота.
- `app/config.py` — все настройки (переменные `.env`).
- `app/core/` — агент, промпты, провайдеры LLM. `app/tools/` — инструменты агента.
- `app/api/` — REST: `auth`, `chat`, `items`, `content`, `finance`, `notes`, `mail`, `notifications`.
- `app/content/` — контент-календарь. `app/finance/` — финансы и цели. `app/notes/` — заметки. `app/mail/` — почта (IMAP только на чтение, OAuth для Outlook).
- `app/monitor/` — дежурство по сайту Forbsa: опрос заявок, проверки, тревоги, регулярные задачи, команды ботов, здоровье сервера Атласа, трафик.
- `app/channels/telegram.py` — Telegram (long polling, голос, пересылка в заметки).
- `app/briefing.py` — утренний брифинг. `app/services/` — бэкапы, распознавание голоса, учёт расходов и т.д.
- `frontend/src/pages/` — страницы: чат, задачи, финансы, контент-план (пастельный дизайн), заметки, почта.

## Два бота

- **Основной (SLX AI BOT)** — личный: общение с Атласом, голос, `/mail`, `/cost`, `/traffic`, `/app`. Ничего про сайт.
- **Рабочий бот Forbsa** (`WORK_TELEGRAM_BOT_TOKEN`, `WORK_TELEGRAM_CHAT_IDS`) — заявки, тревоги по сайту, сводка за неделю, регулярные задачи, `/status` `/leads` `/due` `/how` `/done` `/snooze` `/lastdone` `/mute`. На свободный текст не отвечает моделью.
- Пока рабочий бот не настроен, всё рабочее идёт через основной. Если рабочий бот не может доставить сообщение, оно уходит в основной.

## Локальная разработка (Mac, VS Code)

```bash
git clone https://github.com/SLX-PROF/MYASSISTANT.git && cd MYASSISTANT
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt ruff
cd frontend && npm ci && cd ..
```
Запуск без настоящих ключей (демо-модель, своя папка данных):
```bash
python scripts/hash_password.py        # придумать пароль, скопировать строку PASSWORD_HASH='...'
printf "LLM_PROVIDER=fake\nDATA_DIR=./data\n" > .env
nano .env                              # вставить строку PASSWORD_HASH='...'
cd frontend && npm run build && cd ..
python -m app.main                     # http://127.0.0.1:8000
```
Для интерфейса с горячей перезагрузкой: `cd frontend && npm run dev` (запросы к `/api` проксируются на :8000). Локальный `.env` в git не попадает.

## Проверки перед коммитом

```bash
source .venv/bin/activate
pytest -q                          # все тесты должны проходить
ruff check app tests               # стиль Python
cd frontend && npm run build       # tsc + vite, без ошибок
```
Тесты не ходят в сеть и не требуют ключей. Новые функции сопровождай тестами в `tests/`.
Важные изменения UI проверяй в браузере на размерах телефона (390×844) и iPad (1024×1366).

## Что сделано

Веб-чат и агент, напоминания, задачи, память. Telegram и Mini App. Дежурство по сайту Forbsa: заявки без персональных данных, проверки, тревоги, регулярные задачи. Контент-календарь для девушки: неделя, месяц, вкладка «Соцсети», банк идей, итоги, референсы, площадки, публичный адрес. Финансы: быстрый ввод, лимиты, регулярные платежи, круговая диаграмма, график по месяцам, цели-копилки, сводка по понедельникам. Заметки. Голосовые (faster-whisper на сервере). Утренний брифинг с погодой. Почта: разбор истории с оценкой цены, ежедневная сводка, отписка в один клик, вход в Outlook через Microsoft. Два бота. Бэкапы: ежедневная база и еженедельный архив в Telegram. Алерты по диску и памяти, уведомление после простоя, heartbeat. Счётчик трафика.
